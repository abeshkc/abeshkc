Please modify my planning/reminder app to integrate OpenAI Whisper speech-to-text and connect it to the existing Claude LLM action system.

Goal:
I want to speak natural commands, have Whisper transcribe them, then send the transcription to Claude for intent detection and autonomous app actions.

Example voice commands:
- “Create a reminder for meeting with Yaseen tomorrow at 10 PM.”
- “Create a meeting note with the following text: We discussed the DIEM monitoring plan and agreed to revise the sampling approach.”
- “Schedule an appointment next Friday at 2 PM with the FAO team.”
- “Add a note: review Yemen brief before Thursday.”
- “Find my notes about AgHiN.”

Required workflow:
1. User clicks a microphone button.
2. App records speech.
3. Audio is sent to OpenAI Whisper for transcription.
4. Transcribed text is displayed in a preview box.
5. Transcribed text is sent to Claude LLM.
6. Claude classifies intent and extracts structured fields.
7. App automatically fills the correct text boxes.
8. App performs the action where safe:
   - create reminder
   - create meeting note
   - create appointment
   - search notes
   - update reminder
9. For destructive actions, still ask for confirmation.

Important:
For create actions, the app can act autonomously after transcription and Claude parsing.
For delete or overwrite actions, the app must ask for confirmation.

Implementation requirements:

1. Whisper integration
- Use OpenAI Whisper API or the current OpenAI speech-to-text endpoint.
- Store OPENAI_API_KEY in .env, never hard-code it.
- Add a service such as:
  /services/speech_to_text_service.py
- Function example:
  transcribe_audio(audio_file_path) -> str
- Add graceful error handling for:
  - no API key
  - microphone not found
  - network/API failure
  - empty transcription

2. Audio recording
- Add a microphone button to the UI.
- User clicks “Start Recording”.
- User clicks “Stop Recording”.
- Save temporary audio locally.
- Send the temporary audio to Whisper.
- Delete temporary audio after successful transcription unless debug mode is enabled.

3. Claude action pipeline
Create or update an agent pipeline:

speech audio
→ Whisper transcription
→ Claude intent parser
→ structured JSON action
→ UI auto-fill
→ database action
→ confirmation message

Claude should return only valid JSON in this structure:

{
  "intent": "create_reminder | create_meeting_note | create_appointment | search | update_reminder | unknown",
  "confidence": 0.0,
  "requires_confirmation": false,
  "fields": {
    "title": "",
    "description": "",
    "date": "",
    "time": "",
    "datetime": "",
    "participants": [],
    "tags": [],
    "priority": "normal",
    "recurrence": "none",
    "search_query": ""
  },
  "action_summary": "",
  "missing_fields": []
}

4. UI auto-fill
After Claude returns structured JSON:
- If intent is create_reminder, fill reminder form fields.
- If intent is create_meeting_note, fill meeting note form.
- If intent is create_appointment, fill appointment form.
- If intent is search, run search and show results.
- If confidence is low or required fields are missing, fill what is available and ask user to review.

5. Autonomous actions
- If confidence is high and required fields are present, create the item automatically.
- Show message:
  “Created reminder: Meeting with Yaseen, tomorrow at 10 PM.”
- If confidence is medium or fields are missing, fill the form but do not save automatically.
- Suggested thresholds:
  - confidence >= 0.85: auto-save create actions
  - confidence 0.60–0.84: fill form and ask user to confirm
  - confidence < 0.60: show transcription and ask user to clarify

6. Date/time parsing
- Correctly interpret natural language dates:
  - tomorrow
  - next Friday
  - today at 5 PM
  - Monday morning
- Use the user’s local timezone.
- If timezone is not already configured, add setting for timezone.
- Default timezone can be Asia/Amman unless the app already has a timezone setting.

7. Meeting notes
For commands like:
“Create a meeting note with the following text: ...”
- Title can be generated from the text if not provided.
- The full dictated content should go into the note body.
- Add source_type = voice.
- Store original transcription.

- Log only metadata, not raw audio, unless debug mode is enabled.
