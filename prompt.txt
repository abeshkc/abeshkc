Modify Aria’s startup briefing and ongoing engagement system.

Goal:
When Aria starts, she should give a richer, more meaningful briefing based on the database, not just one short overdue-reminder line.

1. Richer startup briefing

When the app starts, Aria should scan the local database and generate a short but useful briefing.

Include several relevant points such as:
- overdue reminders
- upcoming reminders
- number of tasks completed recently
- meeting notes written recently
- upcoming meetings
- important or urgent items
- recurring reminders
- useful follow-ups based on note text

Example:
“Welcome back. You have 3 overdue reminders, including one marked urgent. You completed 5 tasks this week. You wrote 2 meeting notes yesterday. One note mentions buying a watch — did you already do it?”

2. More than one line on overdue items

If there are overdue reminders, do not show only one generic line.

Show:
- total overdue reminders
- urgent/high-importance overdue reminders
- oldest overdue reminder
- overdue reminders due today/yesterday/this week
- suggested action, such as review or mark done

Keep it concise.

3. Database insight extraction

Add a lightweight “Aria Insight Engine”.

Aria should query the database and extract meaningful information from:
- reminders
- completed tasks
- overdue tasks
- meeting notes
- normal notes
- recurring reminders
- Microsoft-imported meetings if available

The engine should create context-aware insights such as:
- “You completed more tasks this week than last week.”
- “You have several notes related to DIEM.”
- “Your recent meeting notes mention Yemen twice.”
- “You have an unfinished reminder linked to a meeting note.”
- “You have 2 urgent reminders due in the next 48 hours.”

4. Note text analysis

Aria should look at note text and meeting note text for simple useful follow-ups.

Examples:
- If note says “I need to buy a watch”, Aria can ask:
  “One of your notes says you need to buy a watch. Did you do it?”
- If several notes mention the same topic, Aria can say:
  “You have several recent notes mentioning Lebanon. Worth reviewing?”
- If meeting note includes action words like “follow up”, “send”, “review”, “prepare”, “buy”, “call”, Aria can surface them.

Keep this simple and local if possible. Do not send notes to Claude unless the app already has explicit permission/settings for that.

5. Periodic updates every 10 minutes

Every 10 minutes while the app is open, Aria should refresh and display 3–4 relevant insights.

Examples:
- overdue reminder summary
- upcoming task
- completed task count
- recent meeting note summary
- useful note-based follow-up

Do not spam the user with popups.

Preferred behavior:
- update the Aria briefing panel quietly
- optionally show a subtle animation or badge
- avoid repeating the exact same messages repeatedly

6. Relevance and variety

Aria should rank insights by usefulness.

Priority order:
1. overdue urgent reminders
2. reminders due soon
3. meetings today/upcoming
4. recent meeting notes
5. incomplete follow-ups found in note text
6. completed task progress
7. general productivity encouragement

Avoid showing irrelevant or repetitive insights.

7. User controls

Add settings:
- Enable periodic Aria updates
- Update frequency, default 10 minutes
- Number of insights, default 3–4
- Include note-text insights: on/off
- Quiet mode
- Pause Aria updates

8. UI behavior

The Aria panel should show:
- greeting
- 3–4 insight cards or bullets
- last updated time
- refresh button
- optional “Review” button next to actionable insights

9. Tests

Add/update tests for:
- startup briefing includes multiple insight types
- overdue reminders generate detailed insight
- completed task count appears
- meeting notes count appears
- note-text follow-up is detected
- periodic 10-minute refresh is scheduled
- repeated insights are reduced
- settings can disable periodic updates

10. Preserve existing functionality

Do not break:
- voice assistant
- reminders
- notes
- meeting notes
- Microsoft sync
- reminder popups
- sorting
- Claude parser
- local Whisper

Implementation rule:
Patch the current system cleanly. Keep it lightweight and responsive.
